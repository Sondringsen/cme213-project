\begin{abstract}
We build a GPT-2-style transformer training pipeline from scratch in C++/CUDA
with MPI data parallelism on 4$\times$Quadro RTX\,6000 (Turing, sm\_75) ---
no cuBLAS, no NCCL, no autograd. Profiling against the hardware roofline
reveals four training bottlenecks and a fifth inference regime. Register
tiling lifts GEMM from 13.5\% to 58.6\% of FP32 peak; \texttt{float4}
vectorisation brings memory-bound kernels to 64--70\% of HBM peak; fusing
50 per-tensor \texttt{MPI\_Allreduce} calls into one pinned-buffer call
plus pre-allocating backward scratch cut 4-GPU step time from 74.5\,ms to
59.8\,ms, raising strong-scaling efficiency from 55\% to 62\% at $P{=}4$. A
PagedAttention decode kernel raises KV-cache utilisation from 39\% to 88\%
at $B{=}64$ with $\leq$1.6\% indirection overhead and reaches 65\% of HBM
peak ($\approx$435\,GB/s), with outputs bit-identical to a contiguous
reference.
\end{abstract}

\section{Project Description}

We train a decoder-only GPT-2-style transformer~\cite{radford2019} on
sequences of token IDs. Inputs: a batch of $B$ integer sequences of length
$S$. Outputs: per-position vocabulary logits, reduced to a scalar
cross-entropy loss and backpropagated through every parameter with
Adam~\cite{kingma2015}. Each Pre-LayerNorm block applies multi-head causal
self-attention then a two-layer GELU FFN, both with residuals. Notation:
$B$ batch, $S$ sequence, $C$ model dim, $H$ heads, $D{=}C/H$, $V$ vocab.
All tensors FP32 row-major.

\paragraph{Setup.}
Default config: $n_\text{layers}{=}6$, $C{=}256$, $H{=}8$ ($D{=}32$),
$S{=}128$, $V{=}512$ --- about 5\,M parameters, 20\,MB of gradient. Data:
synthetic random tokens (scaling/profiling) and Wikitext-2 (convergence).
Hardware: 4$\times$Quadro RTX\,6000 (Turing, sm\_75) on one shared-memory
node. Peak FP32 16.31\,TFLOPS; peak HBM 672\,GB/s; ridge
$\approx$24\,FLOP/byte. MPI is non-CUDA-aware OpenMPI. A single forward
step has 36+ GEMMs and $O(S^2)$ attention in naive form; realistic batch
sizes outgrow single-GPU memory and per-step latency multiplies into hours
at full scale --- motivating both multi-GPU training and KV-cache
management for inference.

\section{Algorithms and State of the Art}

\paragraph{Dense GEMM.}
cuBLAS~\cite{cublas} reaches 70--80\% of FP32 peak via shared-memory
tiling, register-file accumulation, and (Ampere+) tensor cores. We
implement the shared-memory tiled variant from Boehm~\cite{boehm2022} with
$16{\times}16$ thread-block register tiling. Turing tensor cores support
only FP16/INT8~\cite{micikevicius2018}; we keep everything FP32.

\paragraph{Attention.}
Flash Attention~\cite{dao2022} tiles $Q, K, V$ in SRAM with an online
softmax, reducing memory from $O(S^2)$ to $O(S{\cdot}D)$ at the same output.
We implement FA1 forward; the backward uses the naive $O(S^2)$
materialisation. FA2's recomputation backward~\cite{dao2023} would be
needed for longer sequences.

\paragraph{Distributed training and inference.}
Data-parallel gradient all-reduce is standard.
Horovod~\cite{sergeev2018} and Karpathy's \texttt{llm.c}~\cite{karpathy2024}
bucket gradients before calling MPI/NCCL Allreduce; we implement the same
fusing strategy. Tensor parallelism (Megatron-LM~\cite{shoeybi2019}) is the
alternative when models exceed single-GPU memory --- rejected here because
our 5\,M-parameter model fits trivially on 24\,GB. For inference, vLLM's
PagedAttention~\cite{kwon2023} manages variable-length KV caches via
virtual-memory-style block tables; we implement this for the decode step.

\section{Parallelization Strategy}

\paragraph{System overview.}
Five layers: CUDA kernels, stateful modules (Linear, LayerNormLayer,
EmbeddingLayer, MultiHeadAttention, TransformerBlock), \texttt{GPT2} model,
\texttt{Trainer} (forward $\to$ CE loss $\to$ backward $\to$ Adam), and MPI
wrapper. Hidden states live as $(B{\cdot}S, C)$ flat tensors; attention
reshapes to $(B, H, S, D)$ and back.

\paragraph{GEMM (compute-bound).}
Three variants ($AB$, $AB^T$, $A^TB$). Each uses a $128{\times}128$
output tile in shared memory with a $BK{=}8$ strip across $K$. The thread
block is $16{\times}16{=}256$ threads, each accumulating an $8{\times}8$
register sub-tile (64 FP32 accumulators per thread). The inner $k$-loop
is \texttt{\#pragma unroll}, exposing 64 independent FMAs per smem load
--- raising both arithmetic intensity and effective \emph{occupancy}.
Global loads are coalesced. Shared-memory tiles are declared
\texttt{[TILE][TILE+1]}: the $+1$ padding breaks the stride that would
serialise warp writes onto a single shared-memory \emph{bank}, eliminating
bank conflicts.

\paragraph{Flash Attention and bandwidth-bound kernels.}
Flash Attention tiles $Q, K, V$ into SRAM, maintaining a running max
$m^{(j)}$ and normaliser $\ell^{(j)}$ with online correction
$e^{m^{(j-1)}-m^{(j)}}$. Causal masking is per-tile; one block per
(batch, head, query-tile). LayerNorm uses a two-pass warp reduction
(numerical stability). GELU, Softmax, Cross-Entropy, the LayerNorm output
pass, and the residual \texttt{add\_inplace} use \texttt{float4} 128-bit
loads --- 4 floats per memory instruction, using the full 128-bit memory
bus. Adam is a pure read-modify-write of $\approx$20 bytes per parameter
and is bandwidth-dominated by construction.

\paragraph{PagedAttention decode kernel.}
One block per (request, head). Reads $K, V$ via a per-request block table,
then runs the same Flash-Attention online-softmax recurrence. The
indirection costs one int read per 16 tokens --- well-amortised against
the $16{\cdot}D$-element K/V tile that follows.

\paragraph{MPI data parallelism.}
Each rank owns a full model copy on one GPU
(\texttt{cudaSetDevice(rank \% n\_local\_gpus)}). Three collectives:
\texttt{MPI\_Bcast} once at startup, \texttt{MPI\_Allreduce(MPI\_SUM)}
after each backward, and \texttt{cudaMemset} between steps. Batch
scattering is done locally from a shared step seed (no MPI call). Because
all ranks run an identical Adam update on the same averaged gradient,
weights stay synchronised without further broadcast.

\section{Performance Model}

Three complementary models, one per regime.

\paragraph{Roofline (compute kernels)~\cite{williams2009}.}
Achievable performance is $\min(\text{peak FLOPS},\,B\cdot\text{intensity})$.
Basic tiled GEMM (one output per thread, $T{=}32$) has intensity
$T/4{=}8$\,FLOP/byte --- below the ridge, shared-memory-bandwidth-bound.
With $8{\times}8$ register tiling, intensity rises to 64\,FLOP/byte ---
above the ridge. \emph{Prediction:} register tiling moves GEMM from
memory- to compute-bound. LayerNorm/GELU/Softmax/Cross-Entropy have $O(1)$
intensity and stay memory-bound; the lever is vectorisation.

\paragraph{Decode roofline.}
The PagedAttention decode kernel reads $\text{len}{\cdot}D$ K floats,
$\text{len}{\cdot}D$ V floats, and $D$ query floats per (request, head)
while performing $\approx{}4\,\text{len}{\cdot}D$ FLOPs. Intensity
$\approx$0.5\,FLOP/byte --- two orders of magnitude below the ridge.
\emph{Prediction:} at saturating $B$, decode is bandwidth-bound and the
only lever is layout. Nsight Compute confirms at $B{=}64$: 65\% of HBM
peak ($\approx$435\,GB/s), only 22\% of FP32 peak. At $B{=}1$ the kernel
reaches only 5.4\% of HBM peak --- the grid $(1, H{=}8){=}8$ blocks is too
small for 72 SMs; the kernel is \emph{parallelism-limited}, not
memory-limited. Crossover at $H{\cdot}B \geq 72$, i.e., $B \approx 9$.

\paragraph{Communication and scaling models.}
For \texttt{MPI\_Allreduce} on $n$ bytes, $T(n){=}\alpha{+}n/b_\text{eff}$.
Our standalone fit gives $\alpha\approx 2$--$6\,\mu$s (shared-memory
transport) and $b_\text{eff}\approx 3$\,GB/s. The 20\,MB gradient takes
$\approx$7\,ms purely from bandwidth; PCIe D$\to$H/H$\to$D adds
$\approx$8\,ms not visible in $\alpha{+}\beta n$ alone. With 50 per-tensor
calls, latency overhead is only $50\alpha\approx 300\,\mu$s --- so fusing
should help via cudaMemcpy reduction, not via $\alpha$. Patarasuk--Yuan
ring lower bound~\cite{patarasuk2009}: $2(P{-}1)/P\cdot(\alpha{+}n/b)$.
For scaling, $E(P){=}T_1/(P\,T_P)$; Amdahl serial fraction
$f{=}(1/E_P{-}1)/(P{-}1/E_P)$; 90\% efficiency requires
$T_\text{compute}\geq 10\,T_\text{comm}$.

\section{Benchmarking and Instrumentation}

\paragraph{Tools.}
\texttt{ncu --set full} captures per-kernel TFLOPS, GB/s, occupancy, and
roofline coordinates. Nsight Systems with NVTX markers
(\texttt{forward\_backward}, \texttt{allreduce}, \texttt{optimizer})
annotates the training timeline; the $\approx$30\,ms/step blocking from
per-step \texttt{cudaMalloc} (invisible in coarse \texttt{chrono} timing)
surfaced this way. Per-step training time uses
\texttt{std::chrono::steady\_clock} on rank 0; kernel microbenchmarks
bracket launches with \texttt{cudaEvent}.

\paragraph{Standalone benchmarks.}
\texttt{allreduce\_bench} fits $\alpha{+}\beta n$ for $P\in\{2,4\}$ across
256\,B--64\,MB message sizes (100-trial averages).
\texttt{paged\_attention\_bench} sweeps $B\in\{1,4,16,64,256\}$ on a
truncated-exponential length distribution (mean 64, capped at 128),
recording memory utilisation analytically and decode latency via
\texttt{cudaEvent} (200-iteration averages). Training averages: 20 steps.

\section{Bottleneck Analysis}

Profiling identifies four training bottlenecks and a fifth inference
regime.

\textbf{(1) GEMM below the ridge.} Basic tiled GEMM achieves
2.20\,TFLOPS = 13.5\% of FP32 peak. With one output per thread and
$T{=}32$, intensity is 8\,FLOP/byte --- shared-memory-bandwidth-bound,
not global. Connects to the \emph{warp execution model}: 32 threads
in lockstep, so any idle FMA slot per warp directly cuts throughput.

\textbf{(2) Scalar loads on memory-bound kernels.} LayerNorm, GELU,
Softmax, Cross-Entropy have $O(1)$ FLOP/byte. GELU achieved only
$\approx$17\% of HBM peak: scalar 32-bit loads underutilise the 128-bit
bus, issuing $4\times$ more load instructions than necessary.

\textbf{(3) Per-tensor allreduce.} $\approx$50 separate
\texttt{MPI\_Allreduce} calls per step, each carrying both an MPI startup
($\alpha\approx 6\,\mu$s) and a cudaMemcpy driver overhead --- $\approx$3
\,ms above the fused-call baseline. The dominant cost is not $\alpha$ but
50 sequential D$\to$H/H$\to$D PCIe round trips.

\textbf{(4) Per-step \texttt{cudaMalloc} in backward.}
\texttt{MultiHeadAttention::backward} and
\texttt{TransformerBlock::backward} allocated 18 temporaries per call,
including two $B{\cdot}H{\cdot}S^2$ attention-score matrices ($\approx$4
\,MB each). \texttt{cudaMalloc} is a synchronising call that flushes the
GPU command queue; at $B{=}16$, this caused $\approx$30\,ms/step of
blocking, visible as spikes in Nsight Systems.

\textbf{(5) Decode has two regimes.} The decode kernel is dominated by
neither dense GEMM nor gradient communication. At $B{=}1$ it is
parallelism-limited (5.4\% HBM, 1.6\% FP32: only 8 thread blocks for 72
SMs). At $B{=}64$ it crosses into the bandwidth-bound regime predicted by
$\approx$0.5\,FLOP/byte intensity --- 65\% of HBM peak. At scale the
ceiling is how many concurrent requests fit in memory; Variant 5
addresses this.

Together, (1)--(4) explain why pre-optimisation strong scaling at $P{=}4$
was 55\%: $\approx$30\,ms cudaMalloc + $\approx$18\,ms unfused allreduce +
a 13.5\%-peak GEMM consume most of the parallelism budget.

\section{Algorithmic Variants}

\paragraph{Variant 1: Register tiling for GEMM.}
1-output-per-thread $\to$ $8{\times}8$ register-tiled (64 FP32 accumulators
per thread, $BM{=}BN{=}128$, $BK{=}8$, $16{\times}16$ threads). Throughput
$2.20 \to 9.56$\,TFLOPS (13.5\% $\to$ 58.6\% peak), $4.3\times$
improvement. cuBLAS reaches $\approx$70--80\% on Turing; we reach
$\sim$75\% of that without tensor cores. Figure~\ref{fig:roofline}.

\paragraph{Variant 2: \texttt{float4} vectorised loads.}
Scalar 32-bit loads in GELU, Softmax, Cross-Entropy, LayerNorm output,
and \texttt{add\_inplace} become \texttt{float4} (4 floats per
instruction). Achieved: 430--470\,GB/s (64--70\% of peak), vs.\
$\approx$17\% pre-vectorisation for GELU --- $\approx 4\times$ bandwidth
improvement. Table~\ref{tab:kernels}.

\paragraph{Variant 3: Fused gradient allreduce.}
50 individual calls $\to$ one call on a pinned-host buffer; identical
volume. As $\alpha{+}\beta n$ predicts, latency saving is only $\approx$300
\,$\mu$s; removing 50 cudaMemcpy pairs cuts comm time
$18.6 \to 15.6$\,ms ($\approx$3\,ms). Residual is PCIe-bandwidth-dominated;
the gap to the ring lower bound is the D$\to$H$\to$D round trip,
recoverable only with CUDA-aware MPI.

\paragraph{Variant 4: Pre-allocated backward scratch.}
18 per-step buffers move to constructor time. 1-rank step
$162.7 \to 148.8$\,ms ($\approx$14\,ms saving), isolating cudaMalloc
overhead. With Variant 3, 4-rank step $74.5 \to 59.8$\,ms.

\paragraph{Variant 5: PagedAttention for inference KV-cache management.}
Variants 1--4 attack training; inference is qualitatively different.
Naive serving pads each request's KV cache to the worst-case length; on a
workload of lengths $\sim$Exp(64) capped at 128, this wastes 56--61\% of
allocated memory. Following Kwon et al.~\cite{kwon2023}, we split the
cache into 16-token blocks managed from a global pool; each sequence
holds a block table mapping logical positions to physical blocks. The
decode kernel mirrors Flash Attention's online-softmax recurrence but
reads $K, V$ through the indirection. At $B{=}64$: utilisation
$39.4\%\to 88.0\%$ ($2.24\times$), with only \textbf{1.3\%} latency
overhead (38.5 vs.\ 38.0\,$\mu$s). The kernel reaches 65\% of HBM peak
(\S4), confirming the bandwidth-saturated prediction. Operationally: the
same memory budget serves $2.2\times$ more concurrent requests with no
per-request slowdown, while keeping the kernel in its saturated regime.
Appendix~\ref{app:paged}.

\paragraph{Amdahl and isoefficiency.}
At $P{=}4$ after optimisation, $E_4{=}62\%$, giving
$f \approx 0.25$. This 25\% serial fraction is almost entirely
communication: comm fraction at $P{=}4$ is 26.1\%. For 90\% efficiency,
$T_\text{compute}\geq 10\,T_\text{comm}$. Current $P{=}4$ ratio is
$44/15.6 \approx 2.8$, well below threshold. Two paths to 90\%: increase
compute $\approx 3.5\times$ (local $B$ from 4 to $\approx 14$), or
CUDA-aware MPI to cut comm to $\sim$7\,ms (allreduce-only time, PCIe
staging removed), giving ratio $\approx 6.3$.

\paragraph{Weak scaling.}
Efficiency drops from 100\% to 75\% ($P{=}2$) and 73\% ($P{=}4$): comm
cost is fixed by gradient size, not local batch. At $P{=}4$ the comm
fraction matches strong scaling exactly (26\%). Appendix~\ref{app:weak}.

\section{Correctness and Verification}

\paragraph{Per-kernel.}
Every CUDA kernel is validated against a plain-C++ CPU oracle:
$\text{rel}\leq 10^{-3}$ or $\text{abs}\leq 10^{-5}$ (the absolute guard
prevents near-zero values from spuriously failing). Forward kernels are
also compared to PyTorch references. All forward and backward tests pass:
GEMM ($32^3$--$4096^3$), LayerNorm (fwd+bwd), GELU (fwd+bwd), Softmax,
Cross-Entropy (fwd+bwd), Flash Attention forward, naive attention
backward.

\paragraph{Distributed and PagedAttention.}
Three multi-rank checks. Step-1 loss is bit-identical across
$P\in\{1,2,4\}$ (6.5336) --- \texttt{MPI\_Bcast} and the deterministic
forward are correct. All configurations drive loss toward the
random-token entropy floor; Wikitext-2 trains correctly ($9.27\to <6.0$
over 300 steps at $P{=}4$). At ranks=4 and local\_B=4, strong and weak
step times agree within 0.02\,ms. For PagedAttention,
\texttt{launch\_paged\_attention\_decode} matches the contiguous
reference \texttt{launch\_dense\_attention\_decode} \textbf{bit-identically}
(abs $=$ 0, rel $=$ 0) across all seven test configurations, including
scrambled block-table mappings (which would fail if the indirection were
ignored). Both also match a CPU oracle within FP32 \texttt{expf}
tolerance.

\section{Discussion}

\paragraph{Biggest payoffs.}
Pre-allocating backward scratch and fusing the allreduce together saved
$\approx$14\,ms per step at $P{=}4$ --- almost 20\% of step time. Neither
was visible in coarse \texttt{chrono} timing; both required Nsight
Systems. Register tiling gave $4.3\times$ on GEMM but GEMM is one of many
kernels, so the absolute saving is smaller. \texttt{float4} was a quick
win: 64--70\% of HBM peak with a few lines per kernel.

\paragraph{Limitations and future work.}
The largest remaining lever is CUDA-aware MPI: the $\approx$8\,ms of
D$\to$H/H$\to$D PCIe staging per step would disappear over NVLink. Flash
Attention backward is $O(S^2)$; FA2's recomputation backward~\cite{dao2023}
is needed for longer sequences. BF16~\cite{micikevicius2018} is not
implemented because Turing has no BF16 tensor cores --- they run on
regular CUDA cores at FP32 throughput. On Ampere/Hopper, native BF16
tensor cores would give $4\times$ compute and $2\times$ memory savings.
For inference, the natural PagedAttention extensions are prefix caching
(block sharing for common prompts), copy-on-write beam search, and chunked
prefill. Starting with a bucketed allreduce and pre-allocated scratch from
day one would have saved hours of debugging.
