\begin{abstract}
We build a GPT-2-style transformer training pipeline from scratch in CUDA and MPI, distributed across four GPUs on a single node. We use Nsight Compute and Nsight Systems to
identify what limits performance: matrix multiply sitting far below compute peak, memory-bound kernels under-utilizing bandwidth, redundant MPI synchronization overhead, and dynamic GPU
allocations stalling the backward pass. We address each bottleneck in turn, with register-tiled GEMM, vectorized memory loads, a fused gradient allreduce, and pre-allocated backward scratch buffers.
Together these cut 4-GPU step time by roughly 20\% and raise strong-scaling efficiency from 55\% to 62\%. For inference, we implement a PagedAttention decode kernel that more than doubles KV-cache memory
utilization at large batch sizes with negligible latency overhead.
\end{abstract}

\section{Project Description}

We train a decoder-only GPT-2-style transformer~\cite{radford2019} on
sequences of token IDs. We focus on the fundamental kernels in the transformer architecture and how we can optimize these. We use
synthetic random tokens for scaling and profiling experiments and Wikitext-2 for realistic training dynamics. However, the main focus for the project is profiling and optimization analysis, not a competitive LLM. A single forward
step has 36+ GEMMs and $O(S^2)$ attention in naive form. Realistic batch
sizes easily outgrow single-GPU memory and per-step latency multiplies into hours
at full scale. This motivates both multi-GPU training and KV-cache
management for inference.

\paragraph{Setup.}
Inputs: a batch of $B$ integer sequences of length
$S$. Outputs: per-position vocabulary logits, reduced to a scalar
cross-entropy loss and backpropagated through every parameter with
Adam~\cite{kingma2015}. Each Pre-LayerNorm block applies multi-head causal
self-attention then a two-layer GELU FFN, both with residuals. Notation:
$B$ batch, $S$ sequence, $C$ model dim, $H$ heads, $D{=}C/H$, $V$ vocab.
All tensors FP32 row-major. We use the class compute cluster which has peak FP32 16.31\,TFLOPS; peak HBM 672\,GB/s; ridge
$\approx$24\,FLOP/byte. 
Default config: $n_\text{layers}{=}6$, $C{=}256$, $H{=}8$ ($D{=}32$),
$S{=}128$, $V{=}512$, which gives about 5\,M parameters, 20\,MB of gradient. 

\section{Algorithms and State of the Art}
The below paragraphs discuss some of the algorithms and kernels we implemented. An overview of all implemented kernels can be found in the Appendix in Table \ref{tab:all_kernels}.

\paragraph{Dense GEMM.}
cuBLAS~\cite{cublas} reaches 70--80\% of FP32 peak via shared-memory
tiling, register-file accumulation, and (Ampere+) tensor cores. We
implement the shared-memory tiled variant from Boehm~\cite{boehm2022} with
$16{\times}16$ thread-block register tiling. This is a slightly more optimized version compared to the one we implemented in class as it uses a more aggressive register tiling. Turing tensor cores only support
FP16/INT8~\cite{micikevicius2018}, so we keep everything as FP32.

\paragraph{Attention.}
Flash Attention~\cite{dao2022} tiles $Q, K, V$ in SRAM with an online
softmax, reducing memory from $O(S^2)$ to $O(S{\cdot}D)$ at the same output.
We implement FA1 forward, the backward uses the naive $O(S^2)$
materialization. FA2's recomputation backward~\cite{dao2023} would be
needed for longer sequences.

\paragraph{The full transformer.}
We implement Pre-LayerNorm transformer blocks as in GPT-2~\cite{radford2019},
with Adam~\cite{kingma2015} as the optimizer.

\paragraph{Distributed training and inference.}
The standard approach is to replicate the model on each rank, have each rank
compute gradients on a local mini-batch, and synchronise via \texttt{MPI\_Allreduce}
before the optimizer step. The naive implementation issues one \texttt{MPI\_Allreduce}
per parameter tensor ($\approx$50 calls in our model) each carrying its own
MPI startup latency and a PCIe device-to-host round trip. Horovod~\cite{sergeev2018}
and Karpathy's \texttt{llm.c}~\cite{karpathy2024} instead pack all gradients into
a single contiguous buffer and issue one call. We implement the same strategy. More sophisticated methods with tensor parallelism (Megatron-LM~\cite{shoeybi2019}) can be used when models exceed single-GPU memory. We do not employ this as our 5\,M-parameter model fits trivially on 24\,GB. For inference, vLLM's
PagedAttention~\cite{kwon2023} manages variable-length KV caches via
virtual-memory-style block tables. We implement this for the decode step as discussed in the last guest lecture.

\section{Parallelization Strategy}
This section presents the final optimized design. The bottlenecks that motivated each decision and the variants explored to reach it are covered in Section~\ref{sec:bottleneck}.

\paragraph{System overview.} We organize our system in five layers. CUDA kernels, stateful modules (Linear, LayerNormLayer,
EmbeddingLayer, MultiHeadAttention, TransformerBlock), \texttt{GPT2} model,
\texttt{Trainer} (forward $\to$ CE loss $\to$ backward $\to$ Adam), and MPI
wrapper.

\paragraph{GEMM (compute-bound).}
We implement three GEMM-variants ($AB$, $AB^T$, $A^TB$). Each uses a $128{\times}128$
output tile in shared memory with a $BK{=}8$ strip across $K$. The thread
block is $16{\times}16{=}256$ threads, each accumulating an $8{\times}8$
register sub-tile (64 FP32 accumulators per thread). The inner $k$-loop
is \texttt{\#pragma unroll}, exposing 64 independent FMAs per smem load, raising both arithmetic intensity and occupancy.
Global loads are coalesced. Shared-memory tiles are declared
\texttt{[TILE][TILE+1]}. The $+1$ padding breaks the stride that would
serialize warp writes onto a single shared-memory bank, eliminating
bank conflicts.

\paragraph{Flash Attention and bandwidth-bound kernels.}
Flash Attention tiles $Q, K, V$ into SRAM, maintaining a running max
$m^{(j)}$ and normalizer $\ell^{(j)}$ with online correction
$e^{m^{(j-1)}-m^{(j)}}$ (similar to what we did in the homework). Causal masking is per-tile, one block per
(batch, head, query-tile). LayerNorm uses a two-pass block reduction. The two passes were necessary to avoid catastrophic cancellation when computing the variance. GELU, Softmax, Cross-Entropy, the LayerNorm output
pass, and the residual \texttt{add\_inplace} use \texttt{float4} 128-bit
loads, which gives 4 floats per memory instruction, using the full 128-bit memory
bus. Adam is a pure read-modify-write of $\approx$20 bytes per parameter
and is bandwidth-dominated by construction.

\paragraph{MPI data parallelism.}
Each rank owns a full model copy on one GPU. We use two collectives: \texttt{MPI\_Bcast} once at startup to synchronize initial weights, and \texttt{MPI\_Allreduce(MPI\_SUM)} after each backward pass to
average gradients across ranks. Batch scattering requires no MPI call. All ranks generate the same random shuffle from a shared step seed and each independently selects its own slice, so no data moves over
the network. Because all ranks then run an identical Adam update on the same averaged gradient, weights stay synchronized without a further broadcast.

\paragraph{Non-obvious implementation challenges.}
Two issues required profiler-assisted debugging rather than correctness tests alone. The $+1$ shared-memory tile padding was revealed by Nsight Compute's bank-conflict counters. A unit test passes either way. The second was the per-step \texttt{cudaMalloc} stalls in the backward pass. This was only revealed by the Nsight Systems timeline and is further discussed in Section \ref{sec:bottleneck}.

\section{Performance Model}\label{sec:perf_model}

We use three complementary models to predict how our implementation performs, one per regime.

\paragraph{The Roofline model~\cite{williams2009}} measures whether a kernel is memory- or compute- bound. 
Achievable performance is $\min(\text{peak FLOPS},\,B\cdot\text{intensity})$.
Basic tiled GEMM (one output per thread, $T{=}32$) has intensity $T/4{=}8$\,FLOP/byte,
sitting below the ridge and shared-memory-bandwidth-bound.
With $8{\times}8$ register tiling, intensity rises to 64\,FLOP/byte, above the ridge.
\emph{Prediction:} register tiling moves GEMM from memory- to compute-bound.
LayerNorm, GELU, Softmax, and Cross-Entropy have $O(1)$ intensity and stay
memory-bound. These kernels therefore benefit from more efficient memory management. So with vectorized loads using \texttt{float4} we should get roughly a 4$\times$ better HBM utilization.
The decode kernel sits at $\approx 0.5$\,FLOP/byte, far below the ridge.
With one block per (request, head), the grid has $H{\cdot}B$ blocks. For $H{=}8$
the grid fills 72 SMs only at $B \geq 9$, so small batches are SM-count-limited
before bandwidth even becomes relevant.

\paragraph{Communication and scaling models.}
We model allreduce latency as $T(n) = \alpha + \beta n$, where $\alpha$ captures
per-call startup and $\beta = 1/b$ is inverse bandwidth.
For our 20\,MB gradient, the bandwidth term predicts $\approx 7$\,ms per PCIe
transfer direction. Because our implementation is not CUDA-aware, each call
incurs a D$\to$H copy and an H$\to$D copy, adding $\approx 2n/b_\text{PCIe}
\approx 13$\,ms on top of the network cost.
The gap between the fitted curve and the ideal network bandwidth is therefore
this D$\to$H$\to$D round-trip cost, recoverable only with CUDA-aware MPI.
When we designed the fused-allreduce variant, we expected to recover most of the $\approx$18.6\,ms overhead by eliminating per-call startup. At the time we failed to account for this PCIe round-trip cost, which dominates regardless of call count.


\paragraph{Amdahl and isoefficiency.}
For strong scaling with $T_P = T_\text{compute}/P + T_\text{comm}$, parallel
efficiency is $E(P) = T_1/(P\,T_P)$. Because $T_\text{comm}$ is fixed by
gradient size while $T_\text{compute}$ shrinks with $P$, efficiency degrades as
more GPUs are added. For isoefficiency, maintaining a fixed efficiency as $P$
grows, the total batch must scale proportionally with $P$.

\section{Benchmarking and Instrumentation}\label{sec:bench}

\paragraph{Tools.}
We use Nsight Compute to capture per-kernel
TFLOPS, GB/s, occupancy, and roofline coordinates, and Nsight Systems
to profile the full training timeline. Both runs capture all kernels
over 20 training steps. This allows us to compare measurements with our performance models above. 

\paragraph{Standalone benchmarks.}
\texttt{allreduce\_bench} fits $\alpha{+}\beta n$ for $P\in\{2,4\}$ across
256\,B--64\,MB message sizes (100-trial averages).
\texttt{paged\_attention\_bench} measures decode latency and KV-cache memory utilization across a sweep of batch sizes.

We defer the results and comparison to the performance model to Sections \ref{sec:bottleneck}–\ref{sec:scalability}.

\section{Bottleneck Analysis and Algorithmic Variants}\label{sec:bottleneck}

We consider the implementation that led to the parallelization strategy explained above. First we identify
four training bottlenecks and a fifth inference regime using Nsight Compute and Nsight Systems. We then use these empirical observations to optimize the implementation. We consider 5 different algorithmic variants. Figure \ref{fig:roofline} shows the kernels before and after our optimizations.

\paragraph{Register tiling.}

As predicted GEMM is initially  below the roofline ridge. Without register tiling,
Nsight Compute places GEMM at 2.20\,TFLOPS = 13.5\% of FP32 peak and
8\,FLOP/byte, left of the $\approx$24\,FLOP/byte ridge
(Fig.~\ref{fig:roofline}). The kernel is memory-bound in shared memory, not global memory.
Each thread reads shared-memory tiles without accumulating enough FMAs per read to saturate the FP32 units.

We remedy this by adding register tiling. We extend one-output-per-thread to an $8{\times}8$ register sub-tile. This raises arithmetic intensity from 8 to 64\,FLOP/byte, which crosses the
hardware's ridge point of $\approx$24\,FLOP/byte and shifts the bottleneck from
shared-memory bandwidth to compute. Nsight Compute confirms that throughput rises from 2.20 to
9.56\,TFLOPS (13.5\%$\to$58.6\% of FP32 peak, $4.3\times$). We benchmark against cuBLAS which
reaches 70--80\%. We attain $\sim$75\%
of that (Fig.~\ref{fig:roofline}, Table~\ref{tab:kernels}).

\paragraph{Scalar loads to vectorized \texttt{float4} loads.}

We improve the memory-management of the O(1) kernels. Scalar 32-bit loads in GELU, Softmax, Cross-Entropy, LayerNorm, and
\texttt{add\_inplace} are replaced by \texttt{float4}, issuing one
128-bit transaction per four floats. Nsight Compute confirms the gain and
bandwidth rises to 430--471\,GB/s (64--70\% of HBM peak) across all five
kernels, versus scalar baselines of $\approx$16--18\%.
This is a $\approx4\times$ improvement (Table~\ref{tab:kernels}) as expected.

\paragraph{Per-tensor allreduce to fused gradient allreduce.} Our first implementation had 50 separate \texttt{MPI\_Allreduce}
calls per step each triggering a D$\to$H cudaMemcpy, a collective, and an
H$\to$D cudaMemcpy. The 50 calls cumulate to $\approx$18.6\,ms/step which we want to reduce.



We therefore replace the 50 individual \texttt{MPI\_Allreduce} calls with one contiguous 20\,MB pinned buffer to eliminate redundant startup overhead.
Fitting $\alpha{+}\beta n$ to the \texttt{allreduce\_bench} data gives
$\alpha{=}51.2\,\mu$s for $P{=}2$, so eliminating 49 extra call startups
saves $49{\times}51.2\,\mu\text{s}\approx2.5\,\text{ms}$, consistent
with the measured $\approx$3\,ms gain. The saving is smaller than
what we predicted because fusion does not reduce the total bytes crossing PCIe.
The full 20\,MB gradient still traverses D$\to$H$\to$D in both cases.
At $\approx$3\,GB/s effective PCIe staging bandwidth (Fig.~\ref{fig:comm}) that round trip costs $\approx$13\,ms regardless of call
count and cannot be recovered without CUDA-aware MPI to route gradients directly
over NVLink.

\paragraph{From per-step \texttt{cudaMalloc} in backward to pre-allocated backward scratch.}
 The Nsight
Systems timeline (Fig.~\ref{fig:cudamalloc}) shows $\approx$30\,ms of idle GPU
time per step as \texttt{cudaMalloc} barriers drain the kernel queue. The multi head attention and transformer block allocated 18 temporary buffers in each
call, including two $B{\cdot}H{\cdot}S^2$ attention-score matrices
($\approx$4\,MB each at $B{=}16$).

The eighteen per-step buffers are moved from the backward call to the
constructor, eliminating the $\approx$30\,ms of per-step cudaMalloc barriers. Figs.~\ref{fig:cudamalloc}
and~\ref{fig:cudamalloc_after} show the Nsight Systems timeline before and after.
The allocations and the resulting idle GPU time are absent in the optimized
profile.

\paragraph{PagedAttention for inference.}
 With one block per (request, head), the grid has only $H{\cdot}B$ blocks. At $B{=}1$ this gives 8 blocks for 72 SMs, leaving most of the device idle. At larger $B$ the grid fills the device and the kernel transitions to being bandwidth-limited, consistent with its $\approx$0.5\,FLOP/byte arithmetic intensity.

We improve the memory-management in inference with PagedAttention. Block-table indirection raises KV-cache utilization from 39.4\% to 88.0\%
at $B{=}64$ ($2.2\times$) with only 1.3\% latency overhead, allowing the
same memory budget to serve $2.2\times$ more concurrent requests
(Table~\ref{tab:paged}).








\section{Scalability Analysis}\label{sec:scalability}


Now we consider the third regime for modeling performance by looking at strong and weak scaling. Table~\ref{tab:scaling} (Figs also included in Appendix \ref{app:scaling}) reports strong and weak scaling before and after
applying the four variants involved in training, as described above. At $P{=}1$ there is no allreduce, so Variant~3
contributes zero. The 14\,ms reduction from 162.7 to 148.8\,ms reflects
Variants 1, 2, and 4 combined. At $P{=}4$, all four variants together drop step time
from 74.5 to 59.8\,ms. Communication falls 18.6$\to$15.6\,ms from fusing
(V3) and compute falls 55.9$\to$44.2\,ms from kernel and allocation
optimizations (V1+V2+V4), raising strong-scaling efficiency from 55\% to
62\%.

\paragraph{Amdahl and isoefficiency.}
At $P{=}4$ after optimization, 44.2\,ms is compute and 15.6\,ms is allreduce
(26\% of step time), giving $E_4 = T_1/(4T_4) = 148.8/(4\times59.8) \approx 62\%$.
We get $T_\text{compute}/T_\text{comm} = 44/15.6 \approx 2.8$.
We can increase this ratio in two ways. First, we may increase the local batch (more compute per
allreduce call), or second, we can adopt CUDA-aware MPI to cut comm to $\sim$7\,ms
(removing PCIe staging), giving ratio $44/7 \approx 6.3$.

\paragraph{Weak scaling.}
Efficiency at fixed $B_\text{local}{=}4$ is 75\% ($P{=}2$) and 73\% ($P{=}4$) (see Fig.~\ref{fig:weak}).
Efficiency is below 100\% because at $P{=}1$ there is no allreduce, whereas
for $P{>}1$ every rank pays a fixed $\approx$15.6\,ms allreduce overhead that
does not shrink with local batch size, it is determined by the size of the gradient.
Note that at $P{=}2$, weak efficiency (75\%) is lower than strong (80\%) because strong
scaling at $P{=}2$ gives each rank $B_\text{local}{=}8$, doubling the compute
per allreduce call. At $P{=}4$ both regimes coincide at $B_\text{local}{=}4$ and the weak scaling is better.

\section{Correctness and Verification}

\paragraph{Per-kernel.}
Every CUDA kernel is validated against a plain C++ CPU implementation
with tolerances $\text{rel}\leq 10^{-3}$ or $\text{abs}\leq 10^{-5}$.
The absolute guard prevents near-zero values from spuriously failing.
Forward kernels are additionally compared to PyTorch references.
All forward and backward tests pass. Table~\ref{tab:errors} reports the
achieved errors for each kernel. The PagedAttention decode kernel is
verified against the contiguous reference bit-identically
(abs $=$ 0, rel $=$ 0) across all seven test configurations, including
scrambled block-table orderings that would fail silently if the
indirection were ignored. Both also match a CPU oracle within FP32
\texttt{expf} tolerance.

\paragraph{Distributed training.}
We perform two multi-rank consistency checks. The step-1 loss is
bit-identical across $P\in\{1,2,4\}$ (6.5336), confirming that
\texttt{MPI\_Bcast} and the deterministic forward pass are correct. All
configurations drive loss toward the random-token entropy floor.
On Wikitext-2, the model trains correctly, falling from 9.27 to below
6.0 cross-entropy over 300 steps at $P{=}4$.

\section{Discussion}

\paragraph{Biggest payoffs.}
All four optimizations together cut 4-GPU step time by $\approx$15\,ms
(74.5$\to$59.8\,ms, $\approx$20\%). Register tiling ($4.3\times$ on
GEMM throughput) and \texttt{float4} (64--70\% of HBM peak) were
identified and quantified by Nsight Compute. The allreduce fusion and
scratch pre-allocation were only visible through Nsight Systems timeline
profiling. The former as PCIe staging between the GPU and host, the
latter as cudaMalloc barriers stalling the backward timeline.
Of the four, fused allreduce delivered the least. It saved only $\approx$3\,ms of the anticipated 18.6\,ms and it was not worth it to implement it without CUDA-aware MPI.

\paragraph{Limitations and future work.}
The largest remaining lever is CUDA-aware MPI. The $\approx$8\,ms of
D$\to$H$\to$D PCIe staging per step would disappear over NVLink. Flash
Attention backward is $O(S^2)$ and FA2's recomputation
backward~\cite{dao2023} would be needed for longer sequences.
BF16~\cite{micikevicius2018} is not implemented because Turing has no
BF16 tensor cores, so BF16 arithmetic runs on regular CUDA cores at FP32
throughput. On Ampere/Hopper, native BF16 tensor cores would roughly
halve memory footprint and double matrix-multiply throughput relative to
FP32. Finally, our 5\,M-parameter model on Wikitext-2 reaches a
perplexity floor that is too high for coherent text generation. Scaling
to a full GPT-2 configuration (124\,M parameters) on a larger corpus
may give meaningful inference.
